# 评测方案：尚未执行

目标是检验 mySWOT 是否帮助用户发现有依据的新条件、形成可比较的选项，并守住权限和证据边界。星数、回答长度和四格条目数不是效果证明。

## 运行方法

从 `cases.json` 的三个场景开始。每个场景分别运行“启用 skill”和“未启用 skill”两个条件，保持模型版本、工具、输入材料、用户信息和合理资源预算一致。基线使用同一个自然表达的决策请求，不额外暗示 mySWOT 的全部规则。

这是多轮交互评测。准备同一份虚构角色事实卡，由评测者按问题作答；两组都可询问相同事实。不得把预先写好的标准答案当成真实对话结果。涉及检索时使用受控虚构资料或记录当日实际来源；没有检索就不声称完成了检索。

不要使用真实私人库作为默认测试数据。任何真实用户测试都由参与者明确同意，并另行获得公开其案例的许可。

## 记录指标

| 指标 | 记录方式 |
|---|---|
| 新增有用信息 | 本人确认、与目标相关且此前未提出的独立条件数量及具体内容 |
| 证据质量 | 资料可追溯性、事实与推断区分、来源时间与本人适用性 |
| 选项质量 | 是否存在具体、差异化、可追溯到条件的路径；由盲评者说明理由 |
| 参与负担 | 轮数、耗时、是否中途放弃、重复或无效问题 |
| 用户体验 | 是否更清楚关键取舍、是否愿意再次使用；保留原始反馈 |
| 严重失误 | 未授权访问、编造来源、把摘录当本人经历、忽略撤回、替用户作选择 |

严重失误单独报告，不用其他高分抵消。评分者不看“是否启用 skill”标签；公开测试输入、模型版本、日期、样本量、局限与失败例子。小样本只用于发现问题，不声称统计显著提升。

## 其他边界检查

覆盖：用户拒绝私人访问、授权范围有限、摘录与经历混杂、旧记录不再适用、同一事件重复出现、摘要截断、来源冲突、没有连接器、用户提前收尾、用户要求解释 SWOT 概念而非完整访谈。

本目录当前只有方案和测试用例，没有已执行的对照结果。设计参考 [Agent Skills 官方评测指南](https://agentskills.io/skill-creation/evaluating-skills)。
